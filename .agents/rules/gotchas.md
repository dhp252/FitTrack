# Technical Gotchas & Reference: Spix (FitTrack)

This document tracks execution constraints, environment issues, platform quirks, and code gotchas in the Spix app. Traps specific to one feature live in that feature's README under `.agents/features/`.

---

## 1. Platform & Environment Gotchas

### Use Bun, not npm
*   **Problem**: The lockfile is `bun.lock` and CI installs with `bun install --frozen-lockfile`. Installing with npm or running `npx` can resolve different versions.
*   **Rule**: Use `bun install` and `bunx expo ...`.

### Native modules missing in some builds
*   **Problem**: Health Connect is Android-only; expo-notifications push and Google services are absent from the FOSS flavor; MapLibre may be unavailable. A top-level import of these modules crashes the app on the platforms without them.
*   **Rule**: Load them lazily behind an availability check, as `src/services/healthConnect/index.ts`, `src/services/notifications/index.ts` and `src/services/maplibre.ts` do.

### Native code is generated, patches are scripted
*   **Problem**: `/android` and `/ios` are git-ignored and regenerated by prebuild, so hand edits there are lost. Some native changes are applied by config plugins (`plugins/`) or patch scripts (`scripts/patch-health-connect.js`, `scripts/android-patches/`).
*   **Rule**: Make native changes through a config plugin or the patch scripts, never only in `/android`.

### Files that exist only on the maintainer's machine
*   **Problem**: `/supabase` (database schema, RLS, Edge Functions), `/docs`, `scripts/release.js` and `scripts/newrelease.js` are git-ignored. The `package.json` scripts `release` / `newrelease` and links in `.github/copilot-instructions.md` point to files that aren't in the repo.
*   **Rule**: Don't assume the Supabase schema; `src/services/supabase/database.types.ts` is the only in-repo copy. Ask the maintainer before changing tables or RPCs.

### Outdated agent instructions
*   **Problem**: `.github/copilot-instructions.md` still says Expo 54 / RN 0.81, persistence via AsyncStorage, two locales, and refers to `src/utils/questCalculator.ts` and `calculateQuestTotals`, which no longer exist.
*   **Rule**: Trust `package.json`, the code and `.agents/`. Quests sync through `gamificationStore.syncQuestsWithEntries(entries)`.

### Asynchronous Execution Race Conditions
*   **Problem**: Social stats, challenge progress and auto-share run on debounced timers (`setTimeout` 450–700 ms in `appStore.ts`) after an entry changes. Tests or flows that check the server right after adding an entry can race them.
*   **Rule**: Wait on the resulting state (poll or await the service call), not on a fixed sleep.

## 2. Code & Algorithmic Gotchas

### Entry changes must go through appStore actions
*   **Problem**: XP, quests, badges, social stats and the social feed are updated as side effects of `appStore` actions. Writing `entries` directly (or via `setState`) leaves gamification out of sync.
*   **Rule**: Use `add*`, `updateEntry`, `deleteEntry`, `restoreFromBackup` or `recalculateGamification`.

### `customCreatedAt` marks historical entries
*   **Problem**: Passing `customCreatedAt` to an `add*` action (used by imports and Health Connect) skips the automatic social feed share; entries older than 5 minutes are never auto-shared.
*   **Rule**: Pass `customDate` / `customCreatedAt` for imported data so it isn't announced to friends as a new workout.

### Network features must never block offline use
*   **Problem**: The app is promised to work fully offline. A thrown network error in an AI, social or lookup flow can break a screen that otherwise works offline.
*   **Rule**: Network calls go through `fetchWithRetry` and are guarded by their feature flag (`isSocialAvailable()`, `settings.aiFeaturesEnabled`, `settings.openFoodFactsEnabled`); failures show a message, not a crash.

### Hardcoded colors in newer screens
*   **Problem**: Some newer screens define their own token objects (e.g. `RC` in `src/repCounter/constants.ts`, `app/_progressTokens.ts`, `src/components/run/runTrackerTokens.ts`) instead of `Colors` from `theme.ts`, so they ignore the user's theme preset.
*   **Rule**: New UI uses `theme.ts`. When touching these screens, prefer moving tokens onto the theme over adding more.
